Stash Studio API (1.0.0)

Download OpenAPI specification:

API Support: help@stash.gg URL: https://docs.stash.gg/

APIs for querying a shop's managed product catalog and loyalty program, and for configuring the loyalty program from a partner's own tools. Designed for server-to-server communication between partner backends and Stash services.

Base URLs

Environment Base URL
Test https://test-api.stash.gg
Production https://api.stash.gg

All endpoint paths below are relative to the base URL. For example, to list products in the test environment:

GET https://test-api.stash.gg/sdk/studio/{shop_id}/products

Authentication

Every request is signed with your Ingress API key (HMAC-SHA256). Send the signature in the versioned x-stash-hmac-signature header.

Setup

  1. Go to Stash Studio > Project Settings > API Secrets
  2. Click Generate Secret to create a new key
  3. Keys created through this portal are Ingress keys by default and work with this API (this is the same key used for /sdk/ API authentication)
  4. Store the secret securely; you will need it to sign every request

Signing a Request

  1. Take the current time as a Unix timestamp in milliseconds, for example 1790000000000
  2. Build the string to sign as {timestamp}.{body}. For GET requests {body} is empty. For PUT requests it is the request body exactly as you send it (the same bytes; do not re-serialize the JSON after signing)
  3. Compute HMAC-SHA256 of that string with your API secret and Base64-encode the result
  4. Send the header x-stash-hmac-signature: v1;{shopId};{timestamp};{base64Signature}. The timestamp must be within 5 minutes of Stash server time

Example (curl)

TS=$(($(date +%s) * 1000))
BODY=""   # for PUT, the exact JSON you will send, e.g. BODY='{"activate":true}'
SIGNATURE=$(printf '%s' "${TS}.${BODY}" | openssl dgst -sha256 -hmac "YOUR_API_SECRET" -binary | base64)
curl -H "x-stash-hmac-signature: v1;{shop_id};${TS};${SIGNATURE}" \
  "https://test-api.stash.gg/sdk/studio/{shop_id}/products"

Legacy header (deprecated)

stash-hmac-signature carries an untimestamped Base64 HMAC-SHA256 of the body alone (empty string for GET). It is still accepted but is replayable; use the versioned header for new integrations and for every configuration write.

List published products

Retrieves a paginated list of published products with active offers for a shop. Results are ordered by creation date (most recent first). Only published products whose offer window contains the current time are returned; drafts, deleted products, and offers outside their schedule are excluded.

Maximum results per page. Defaults to 50. Maximum allowed value is 100.

offset
integer <int64>

Pagination offset. Use next_offset from the previous response to fetch the next page. Defaults to 0.

Configure a loyalty season

Creates or updates one loyalty campaign (season) together with the shop-level display settings, bonus definitions and reward products it depends on, and optionally activates the program. The campaign id is the upsert key: an existing id updates that season, a new id creates one. The request describes the whole season it names, so a tier or milestone omitted from it is removed from that season; bonuses and reward products are created or updated by id or SKU and never removed. Draft and scheduled seasons accept every change. An active season accepts names, descriptions, images, milestone rewards, tier earn rates and a new end date; thresholds, adding or removing tiers or milestones, the start date and reset rules are refused with FAILED_PRECONDITION listing the fields. Ended seasons are read-only. The request body must be signed exactly as sent. Applying is idempotent: after a 500, resend the same request. Returns INVALID_ARGUMENT with per-field violations when validation fails, PERMISSION_DENIED when the shop is not enabled for configuration writes, ABORTED when another update for the shop is in progress, and NOT_FOUND for an unknown shop.

Authorizations:
hmac
path Parameters
shopId
required
string

Shop identifier from Stash Studio

Request Body schema: application/json
required
activate
boolean

Turn the program on once the request has been applied and passes publish validation. Honoured only when the program is not live (never published, or unpublished in Studio); ignored on a live program. Creates the program for the shop if it has none.

object (Loyalty Display Config)

Shop-level display settings, overwritten as sent. Omit to leave them unchanged.

Array of objects (Loyalty Bonus Definition)

Bonus definitions, created or updated by id. A bonus missing from the list is left in place; the API never deletes bonuses because wallet balances depend on them.

Array of objects (Loyalty Reward Product)

Reward products, created or updated by SKU. Every product listed is published on write, including one saved as a draft in Studio; leave a product out of the list to keep its Studio draft unpublished. A product missing from the list is left in place; the API never deletes products because claimed milestones and ended seasons still refer to them. Applied before the campaign, so a milestone may reference a SKU defined in the same request.

required
object (Loyalty Campaign Config)

The season to create or update; its id is the upsert key. The season is replaced as a whole: a tier or milestone omitted from it is removed from that season. Other seasons are not touched.
